# 网页迁移执行计划
更新：2026-10-29

目标：由 GitHub 部署的手机优先网页，保留小程序既有修复测试逻辑，增加自愿信息问卷与邮件/企业微信通知。

## 交付
1. 原生静态前端、原图和推荐规则；修复方向→牙位→两题→结果→信息问卷→提交回执。
2. 独立服务端通知接口；严格校验、同意记录、来源限制、限流、重复请求处理；密钥仅服务端。
3. GitHub Pages Actions 和通知服务部署配置；新仓库不包含小程序历史资料与私人数据。
4. 自动规则回归及服务失败测试；手机宽度320/375/430和桌面实览、可用控件与真实错误反馈。

## 当前状态
用户已确认静态HTML＋GitHub Pages、保留蓝白风格、邮件通知及三个选填字段。页面与接口实现完成，19项测试/120组合通过，手机视口及桌面关键页面已观察，隔离模拟提交成功/失败均验证。已初始化独立main分支。测试收件者仅保存于Git忽略的.dev.vars。

尚待：GitHub用户名/仓库、邮件服务授权与验证发件身份、可公开项目联系途径、Cloudflare部署及真实邮箱收件联调。尚未上线，未发真实邮件。整体交付未标记为全部验收完成。

## 验收门槛
- 所有八条树脂与四条牙冠排序、3/4分界与匹配度100%一致。
- 禁止前后牙混选，返回修改类型清答案，改变龋齿牙区清相关评分。
- 不收集额外身份信息；联系人在页面内存中，刷新丢弃；仅明确同意后发送。
- 请求失败、超时、配置缺失显示可操作的真实错误；不作假成功。
- 前端发布目录不包含密钥、服务端环境文件、接收者邮箱和测试截图。
- 所有网络通知使用测试桩验证；真实收件人联调与公开发布需实际配置闭环。

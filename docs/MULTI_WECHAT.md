# 多个微信同时接收

2026-11-02，v1.4。用户已确认每份问卷发送给所有配置的微信，不按修复项目分配。

## 更新已部署的后台

1. 解压 `dental-guide-web-multi-wechat-update-v1.4.zip`，将文件按原目录上传至现有GitHub仓库根目录并提交main。
2. 已连接该仓库的Cloudflare Worker会重新构建部署；查看最新构建结果。仍使用 `npm test` 和 `npx wrangler deploy`，根目录为 `/`，后台名仍是 `dental-guide-notify`。
3. 打开该Worker的Settings → Variables and Secrets，添加Secret类型的变量 `SERVERCHAN_SENDKEYS`。值填每个接收人的SCT密钥，每行一个；也支持英文逗号分隔。不要写入wrangler.toml、GitHub源码或网页变量。
4. 将原来那个微信也列入多人密钥中。非空的多人配置会替代单人配置；原来的 `SERVERCHAN_SENDKEY` 可以保留作为未来恢复单人模式的配置。
5. 继续保留运行Secret `IP_HASH_SALT`，并使新Secret配置生效。只在本地填值不会同步到Cloudflare。

多人格式示意（占位内容不能直接用作真实密钥）：

```text
SCT第一个人的实际密钥
SCT第二个人的实际密钥
```

最多10个不同密钥，重复项自动去重；任意一个格式错误都会阻止发送，避免遗漏接收人。只接受Server酱Turbo的SCT格式。

## 发送与重试

- 一份问卷并行发给名单中所有微信，内容一致；所有接收通道均获接口确认后才向网页返回成功。
- 部分人确认、部分人失败时，返回可重试提示，已确认的人不重复补发。调整名单顺序不影响确认记录，服务重启后仍可继续。
- 新增名单不会补发已经完成的旧回执；新问卷使用当前配置。尚未完成的回执重试时使用当前有效名单。
- 只保存接收密钥的不可逆指纹及发送状态，不在存储记录中保存原始密钥、联系方式或问卷正文。
- 上游收到但响应丢失、状态写入失败等情况可能仍导致重试重复消息，不能保证绝对一次；本项目不自动循环重试。

## 费用与接收范围

每个不同SendKey都会各调用一次Server酱，按其所属账户额度计算；多人不会合并成一次推送。不要据此承诺多人免费额度共享或叠加，实际额度以每个账户后台为准。

正式开放问卷前，网页的信息用途应说明发送给项目负责团队；推荐设置 `PUBLIC_NOTIFICATION_LABEL` 为“看牙有谱项目负责团队（多人微信，经Server酱通知服务）”，同时补齐用户同意公开的联系途径。仅查看材料结果不会发送问卷。

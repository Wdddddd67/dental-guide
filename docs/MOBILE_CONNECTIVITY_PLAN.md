# 手机网络连接排查与免费候选方案

更新：2026-11-02。用户确认：同一手机网络无法打开现有workers.dev后台的/api/health；电脑能够提交并收到微信，手机提交等待后超时。用户没有域名，优先免费。

## 已知与未知

当前证据指向手机到后台域名的网络可达性，不指向选牙规则或微信接收密钥。尚不能区分DNS、运营商路径、拦截等具体原因；不认定必须使用代理。既有Cloudflare后台和多人微信推送保留。

## 免费候选：先验证Supabase默认项目域名

[Supabase免费方案](https://supabase.com/pricing)当前为0美元/月，最多两个活跃免费项目；闲置一周可能暂停。官方[函数入门](https://supabase.com/docs/guides/functions/quickstart-dashboard)提供平台分配的HTTPS函数地址，无需先购买自有域名。不能据此保证从中国大陆或每个手机网络都可达。

执行顺序：

1. 本人登录Supabase，选择Free创建项目。无需迁移现有网站，不添加微信密钥或真实问卷。
2. 取得后台显示的Project URL。先用发生故障的手机网络打开它；哪怕返回JSON错误/401/404，也表示网络已到达服务端，应和连接超时区分。
3. 如需精确探测，在新的Edge Function中粘贴 `connectivity-probes/supabase/index.ts`，函数名为dental-connectivity。该函数只有只读测试功能，不读取密钥、不记录请求正文、不发送消息。若将此新测试函数配置成公开访问，范围仅限此只读函数，不修改现有服务的鉴权。
4. 手机、电脑分别打开平台显示的该函数URL；看到reachable:true且notificationsEnabled:false证明这个测试地址可达。401说明鉴权层可达，不能误报成网络超时。
5. 只有手机连通性通过后，再准备接入现有通知后台的适配方案。正式接入必须继续保留服务端密钥、同意要求、原排序、多人确认与失败补发，不把SendKey移到网页。
6. 修改线上PUBLIC_API_BASE_URL前完成虚构问卷验收；维持既有电脑可用入口，避免先改线上再测试。

本轮只是候选调查和只读测试代码准备，没有注册账号、创建云资源、部署新接口、迁移问卷、购买域名或开通付费服务，也没有发送额外通知。
